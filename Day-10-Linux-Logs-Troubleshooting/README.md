## 1. Linux Logs

Linux logs record events generated by:

- Operating system
- Kernel
- Services
- Applications
- Authentication systems
- Users

Examples include:

```text
Service started
Service stopped
SSH login
Authentication failure
Kernel event
Application error
Network event
```

Logs provide evidence when troubleshooting system problems.

---

## 2. `/var/log`

Traditional Linux log files are commonly stored under:

```bash
ls -lah /var/log
```

Depending on the distribution and configuration, common files may include:

```text
/var/log/syslog
/var/log/auth.log
/var/log/kern.log
```

Some services may have their own log directories.

---

## 3. systemd-journald

Modern Linux systems using systemd commonly use `systemd-journald` to collect logs.

The main command for querying the journal is:

```bash
journalctl
```

---

## 4. Basic journalctl

View journal entries:

```bash
journalctl
```

View the latest 50 entries:

```bash
journalctl -n 50
```

Follow logs in real time:

```bash
journalctl -f
```

Stop following with:

```text
Ctrl + C
```

---

## 5. Service-Specific Logs

For Nginx:

```bash
sudo journalctl -u nginx
```

Latest 50 entries:

```bash
sudo journalctl -u nginx -n 50
```

Follow Nginx logs:

```bash
sudo journalctl -u nginx -f
```

The `-u` option filters logs by systemd unit/service.

---

## 6. SSH Logs

Depending on the Linux distribution and service naming:

```bash
sudo journalctl -u ssh
```

or:

```bash
sudo journalctl -u sshd
```

Check the actual service:

```bash
systemctl status ssh
```

or:

```bash
systemctl status sshd
```

---

## 7. Logs from Current Boot

View logs from the current boot:

```bash
journalctl -b
```

View errors from the current boot:

```bash
journalctl -b -p err
```

View the previous boot:

```bash
journalctl -b -1
```

This can help investigate problems that occurred before a reboot.

---

## 8. Time-Based Log Filtering

View logs from the last hour:

```bash
journalctl --since "1 hour ago"
```

Today:

```bash
journalctl --since today
```

Yesterday:

```bash
journalctl --since yesterday
```

Specific time range:

```bash
journalctl --since "2026-10-02 20:00:00" --until "2026-10-02 21:00:00"
```

Time filtering is useful when investigating an incident that occurred during a known period.

---

## 9. Log Priorities

Common journal priorities include:

```text
0 → emerg
1 → alert
2 → crit
3 → err
4 → warning
5 → notice
6 → info
7 → debug
```

Show errors:

```bash
journalctl -p err
```

Show errors from the current boot:

```bash
journalctl -b -p err
```

---

## 10. Kernel Logs with dmesg

`dmesg` displays messages from the Linux kernel ring buffer.

```bash
dmesg
```

Human-readable timestamps:

```bash
dmesg -T
```

View recent kernel messages:

```bash
dmesg -T | tail -50
```

Search for errors:

```bash
dmesg -T | grep -i error
```

Search for failures:

```bash
dmesg -T | grep -i fail
```

---

## 11. Traditional Log Files

View recent system log entries:

```bash
sudo tail -50 /var/log/syslog
```

Follow the system log:

```bash
sudo tail -f /var/log/syslog
```

Authentication logs on Ubuntu/Debian may be available at:

```bash
sudo tail -50 /var/log/auth.log
```

Search authentication failures:

```bash
sudo grep -i "failed" /var/log/auth.log
```

The exact log files vary by Linux distribution and logging configuration.

---

## 12. tail

View the last lines of a file:

```bash
tail /var/log/syslog
```

Last 50 lines:

```bash
tail -50 /var/log/syslog
```

Follow a log:

```bash
tail -f /var/log/syslog
```

## 13. less

For large log files:

```bash
less /var/log/syslog
```

Useful keys:

```text
↑ ↓      Move
Space    Next page
b        Previous page
/word    Search
n        Next match
q        Quit
```

---

## 14. grep

Search for a keyword:

```bash
grep "error" /var/log/syslog
```

Case-insensitive:

```bash
grep -i "error" /var/log/syslog
```

Search multiple patterns:

```bash
grep -Ei "error|fail|critical" /var/log/syslog
```

---

## 15. Combining Commands

Linux commands can be combined using pipes.

Example:

```bash
sudo journalctl -u nginx -n 100 | grep -Ei "error|fail"
```

This:

1. Retrieves recent Nginx logs
2. Passes the output to `grep`
3. Filters for errors or failures

---

## 16. Real-Time Log Monitoring

One useful troubleshooting technique is to follow a service's logs while generating activity.

Terminal 1:

```bash
sudo journalctl -u nginx -f
```

Terminal 2:

```bash
curl http://localhost
```

This allows me to observe log activity while making a request to the application.

---

## 17. Log Rotation

Logs can grow continuously and consume disk space.

Linux commonly uses `logrotate` to manage log files.

Check the version:

```bash
logrotate --version
```

Main configuration:

```bash
cat /etc/logrotate.conf
```

Application-specific configurations:

```bash
ls -la /etc/logrotate.d/
```

Log rotation can:

- Rotate old logs
- Compress old logs
- Retain logs for a configured period
- Prevent logs from growing indefinitely

# 🔐 SSH Troubleshooting

If SSH is not working:

### 1. Verify the IP/DNS

```bash
hostname
```

### 2. Check network connectivity

```bash
ping SERVER_IP
```

### 3. Check TCP port 22

```bash
nc -vz SERVER_IP 22
```

### 4. Check SSH service

```bash
sudo systemctl status ssh
```

### 5. Check listening port

```bash
sudo ss -lntp | grep ':22'
```

### 6. Check SSH logs

```bash
sudo journalctl -u ssh -n 50
```

### 7. Use verbose SSH output

```bash
ssh -vvv user@SERVER_IP
```

# 🌐 Nginx Troubleshooting

If Nginx stops working:

```bash
sudo systemctl status nginx
```

Check logs:

```bash
sudo journalctl -u nginx -n 50
```

Validate configuration:

```bash
sudo nginx -t
```

Check port:

```bash
sudo ss -lntp | grep ':80'
```

Test locally:

```bash
curl -I http://localhost
```

# 💾 Disk Troubleshooting

If disk space suddenly becomes full:

```bash
df -h
```

Find large directories:

```bash
sudo du -xhd1 / | sort -h
```

Inspect logs:

```bash
sudo du -sh /var/log/*
```

Check inode usage:

```bash
df -ih
```

Check deleted files still held open:

```bash
sudo lsof +L1
```

# 🎤 Interview Questions

### 1. Where are Linux logs stored?

Traditional log files are commonly stored under `/var/log`, while systemd-based systems also maintain logs in the systemd journal.

### 2. What is journalctl?

`journalctl` is a command used to query and analyze logs collected by systemd-journald.

### 3. How do you check logs for a service?

```bash
journalctl -u SERVICE_NAME
```

Example:

```bash
journalctl -u nginx
```

### 4. How do you follow logs in real time?

```bash
journalctl -f
```

or:

```bash
journalctl -u nginx -f
```

### 5. How do you view logs from the current boot?

```bash
journalctl -b
```

### 6. How do you view only errors?

```bash
journalctl -p err
```

### 7. What is dmesg?

`dmesg` displays messages from the Linux kernel ring buffer and is useful for investigating kernel, driver, hardware, and boot-related events.

### 8. What is log rotation?

Log rotation manages growing log files by rotating, compressing, and retaining older logs according to configured policies.

### 9. How would you troubleshoot an SSH problem?

I would check network reachability, TCP port 22, firewall/security rules, the SSH service, the listening port, authentication configuration and permissions, SSH logs, and finally use `ssh -vvv` for detailed client-side diagnostics.

### 10. How would you troubleshoot a failed Nginx service?

I would check `systemctl status nginx`, inspect `journalctl -u nginx`, validate the configuration with `nginx -t`, verify the listening port, and test the application locally with `curl`.
